# 真实性与风险检查

所有成稿在交付前必须执行本检查。传播性不能覆盖真实性。

## 绝对规则

不得编造吴迪的客户、价格、销量、经历、事故、冲突、报价、竞争对手行为、引用、行业统计或结果。

当脚本结构需要真实经历，但 `source_material` 没有提供足够事实时，`script.real_story` 使用明确占位：

`【这里需要补吴迪真实经历】`

同时把所需素材写入 `missing_material`，例如“补充一次真实客户沟通经历：发生时间、场景、客户问题、吴迪当时的判断”。缺失的真实经历槽位绝不能被静默填充，不得用虚构案例填空。

## 具体数字

任何未经来源支持的具体数字，包括价格、百分比、亩产、销量、成本、日期、市场份额和时间跨度，都不能作为事实写入成稿。

处理顺序：
1. 有可靠 `source_material`：可以使用，并保持原语义和限定条件。
2. 没有可靠来源但数字不是核心：删除数字，改成模糊表达，避免制造虚假精确度。
3. 数字是核心论据：加入 `missing_material` 并标记待核实，要求补来源后再成稿。

## 五项发布前检查

1. **虚构经历**：出现用户未提供的具体客户/事件/对话时删除或标记缺失素材。
2. **无来源数据**：具体数据无支持时删除、模糊表达或标记待核实。
3. **攻击同行**：把针对个人/公司的攻击改为可验证的行业现象；不得暗示未证实的违法或欺诈。
4. **农业恐慌**：不得用灾难、绝收、食品安全等恐惧词制造无依据焦虑。
5. **广告过重**：若产品名或购买引导压过人物观点，删减销售话术，恢复内容价值。

## 事实与观点分层

- 事实：必须来自用户提供的可靠素材或可核实来源。
- 吴迪观点：可以鲜明，但要明确是个人判断/经验，不包装成行业定论。
- 推测：必要时使用“我个人更倾向于”“通常要结合具体情况”等限定，不把推测升级为事实。
